# Harness 测试与验收

## 统一入口

```powershell
npm run harness:verify
```

该命令依次执行单元/回归测试、TypeScript 类型检查和前端构建。它失败时，修改未完成。

## 无设备验收

```powershell
npm run simulate
```

访问 http://localhost:3001，连接模拟魔方并确认复原后点击「一键自检」。覆盖成绩核验取消、正常成绩与首页统计、成绩结束后的连续换轮、失败重试和连续专项。可使用剩余打乱 / 动作序列、延迟回读 / 释放、模拟断连与姿态做定向检查。只替换验收构建中的 GAN 驱动，其他业务代码与正式应用共用；测试成绩和 3000 隔离，诊断不落盘、模型不联网。

UI、3D 视角、计时和训练控制器修改默认采用模拟验收，不要求用户重复断联和配对。真实蓝牙配对、加解密、通知时序或传感器轴向有改动时，再安排对应设备补测；未做硬件验收必须明确记录。

## 按风险选择的附加验证

| 改动类型 | 必需验证 |
| --- | --- |
| 纯算法、公式、打乱、校验 | 对应 `*.test.ts` + `npm run harness:verify` |
| UI / 3D 视角 / 计时与专项控制器 | 模拟一键自检 + 桌面 / 手机布局，必要时延迟回读或模拟断连 |
| 公式库视觉 | 构建后检查 F2L、OLL、PLL 三个标签页；OLL 灰色只代表无关朝向，PLL 顶面保持黄色 |
| 后端 / 启动脚本 | `/api/health`、启动失败清理、端口 3000 无残留 |
| BLE / 陀螺仪 | 原始包 fixture、解析器单测、至少一次对应设备真机连接 |
| 成绩与复盘 | 已还原、未还原、丢步、时间戳回绕/乱序样本都要覆盖 |

## 失败处理

- 不允许通过降低断言、删除 fixture 或标记跳过来“修复”失败。
- 测试受环境限制（例如无法监听端口）时，记录限制、已完成的替代验证和待补测项。
